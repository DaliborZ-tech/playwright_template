# 01 · Co vlastně automatizujeme

Regresní test ověřuje, zda dříve fungující chování zůstalo funkční po změně.
Manuálně byste otevřeli portál, zadali přístupové údaje a zkontrolovali přehled.
Automatizace provede stejnou cestu podle přesně popsaných pravidel. Užitečná
je hlavně při opakování stabilních scénářů. Průzkumné testování a úsudek QA
tím nekončí: test zná jen očekávání, která mu napíšete.

Python je jazyk zápisu. pytest soubory najde, připraví testovací prostředí a
vyhodnotí výsledek. Playwright provede kroky v prohlížeči. Chromium vykreslí
skutečnou aplikaci. Tento vztah není řetězec simulací: test opravdu kliká na
HTML prvky a server opravdu ukládá změny do oddělené paměťové relace.

Spusťte `scripts\start_demo.cmd`, otevřete http://127.0.0.1:5000 a přihlaste
se účtem z README. Otevřete Záznamy a ručně vytvořte požadavek. Potom spusťte
`scripts\run_regression.cmd`. Automatická sada má jinou relaci a vlastní port;
váš ručně vytvořený záznam tam správně není. Tím vznikají opakovatelné podmínky.

V `tests/smoke/test_login.py` si přečtěte `test_01_open_application`.
`goto` odpovídá otevření stránky, `expect` porovnává skutečnost s očekáváním.
Samotné otevření bez kontroly nadpisu by neprokazovalo, že je správný obsah.

**Úkol 01:** Napište tři řádky manuálního test case pro otevření přihlášení:
předpoklad, akce, očekávaný výsledek. Potom vyhledejte odpovídající řádky
v testu. Spusťte řešení `training/solutions/test_01_open.py`.
Úkol je hotový, když vysvětlíte, co by způsobilo selhání tohoto ověření.
